# Milestone 6 Evidence

## Goal
Review one imperfect week. Select an ending day and display the previous seven logical days. Let the user enter five optional indicators and four questions. Show recorded evidence. Add static orientation for the four 30-day periods.

## Packages Changed
- `domain`: `ReviewModels.kt` (WeeklyReview, ThirtyDaySequence)
- `data`: `ReviewEntity.kt`, `ReviewDao.kt`, `SteadyDatabase.kt`
- `ui`: `ReviewViewModel.kt`, `ReviewScreen.kt`, `SteadyAppNavigation.kt`

## Implementation Details
- **Data Selection**: `ReviewViewModel` calculates a 7-day window ending on the current `logicalDay` and queries `ReviewDao.getPlansInWindow` to retrieve the `DailyPlanEntity` records for those dates.
- **Sparse Data Handling**: The `ReviewScreen` uses `.ifEmpty { "None" }` to prevent sparse data from displaying awkwardly. If no plans exist, it gracefully reports "Not recorded" rather than assigning a failing zero score.
- **Orientation Content**: A Card displaying the `ThirtyDaySequence` strings is toggled via a top app bar action.
- **UI State**: Form fields cover five indicators (sleep, learning, building, health/movement, connection) and four reflection questions. These are durably saved using the `WeeklyReviewEntity` mapping back to the `weekEnd` date as the primary key.
